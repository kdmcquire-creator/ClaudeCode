Phase Skills

PHASE 1 Intake

Parses raw user input into a structured research plan. Extracts name, company, meeting type, relationship status, and known facts. Generates 6-10 targeted search queries optimized by meeting context. Classifies across 6 types: deal, hiring, investor, networking, board, general.

CHECKPOINT ≥6 search queries · meeting_type classified · full name present (if only first name → ask ONE question)
HANDOFF → research_plan object with subject_name, current_company, meeting_type, relationship_status, known_facts[], search_queries[], priority_signals[]

PHASE 2 Research

Executes search queries in 3 batches (identity → career depth → context enrichment). Fetches key pages. Cross-references every fact with verification tiers: confirmed, likely, or unconfirmed. Time-boxed to 8-12 tool calls. Identifies shared ground with Kyle's profile (Peak 10, Austin/Houston, PE-backed E&P).

CHECKPOINT current role + ≥1 prior role confirmed · confidence ≥ medium · if low → 3 additional searches, then flag gaps
HANDOFF → raw_intel object with bio_facts, current_role, career_arc[], public_content[], company_context, shared_connections[], source_urls[], confidence_score, gaps[]

PHASE 3 Synthesis

Transforms raw intel into 7 editorial sections. Writes a career arc narrative (not a resume dump). Generates conversation topics prioritized by meeting type. Creates calibrated openers by relationship status. Produces tactical notes specific to the meeting's strategic purpose. Target: 400-600 total words.

CHECKPOINT 7/7 sections populated · ≥4 conversation topics · ≥3 openers · ≥2 avoid items · no fabricated facts · 400-600 word count
HANDOFF → brief_content object with header, career_arc, snapshot, conversation_topics[], openers[], tactical_notes, avoid[]

PHASE 4 Format

Renders brief_content into a single-page PDF using reportlab. Layout: dark header band → career arc → two-column body (snapshot + openers | conversation topics) → bottom strip (tactical notes + avoid). Color palette driven by meeting type. Overflow handling: trim topics → trim openers → tighten notes → reduce font.

CHECKPOINT PDF exists · ≥1 page · ≤2 pages · file size 10KB-5MB · pypdf validation pass
